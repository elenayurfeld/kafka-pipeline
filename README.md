# kafka-pipeline

Песочница Kafka: один брокер в KRaft, продюсер и консьюмер событий задач,
отвод битых сообщений в DLQ.

## Поднять брокер

```bash
docker compose up -d
```

Брокер на `localhost:9092`, Kafka UI на http://localhost:8080.

## Прогнать поток

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python -m pipeline.consumer          # в одном терминале
python -m pipeline.producer --count 10   # в другом
```

Топики `task-events` и `task-events.dlq` создаются автоматически
(`KAFKA_AUTO_CREATE_TOPICS_ENABLE=true`).

## Тесты

```bash
pytest
```

Брокер для тестов не нужен: вся логика разбора и проекции лежит в
`pipeline/processing.py` и `pipeline/events.py`, которые не импортируют aiokafka.

## Решения, которые стоит знать

Ключ сообщения — `task_id`, чтобы события одной задачи попадали в одну
партицию и порядок смены статусов сохранялся. Продюсер идёт с `acks=all` и
`enable_idempotence=True` — иначе ретрай даёт дубли и дыры в порядке.
Консьюмер коммитит оффсеты вручную после обработки: автокоммит теряет
сообщения при падении посреди батча. Доставка остаётся at-least-once, поэтому
проекция дедуплицирует по `event_id`.

Битое сообщение уходит в DLQ, а чтение продолжается — иначе одно кривое
сообщение встаёт поперёк партиции навсегда. В каждом событии едет
`schema_version`: консьюмер отказывается от незнакомого формата внятно,
а не падает на разборе.

## Чего тут намеренно нет

Брокер без TLS и без SASL, Kafka UI без аутентификации. Только для локальной
машины, наружу не выставлять. Реестра схем нет — контракт описан кодом в
`pipeline/events.py`.
